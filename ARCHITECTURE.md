# Архитектура системы Biblio

## Обзор

Biblio построена по клиент-серверной архитектуре. Все компоненты находятся в одной локальной сети. Связь между сервером и клиентами осуществляется через SignalR (постоянное соединение) и REST API (разовые запросы).

---

## Схема развёртывания

```
Локальная сеть
│
├── Серверный ПК
│   ├── BibAdmin.exe          ← десктопное приложение администратора
│   └── BibAdminWeb           ← встроенный веб-сервер (ASP.NET Core, порт 8080)
│       ├── /hub              ← SignalR: связь с клиентскими ПК
│       ├── /adminhub         ← SignalR: десктопный BibAdmin
│       └── /webhub           ← SignalR: операторы через браузер
│
├── Клиентский ПК × N (30–50 шт.)
│   ├── BibClient.exe         ← полноэкранное приложение блокировки
│   ├── BibClientService      ← Windows-сервис, перезапускает BibClient при падении
│   └── BibClientGuardian     ← watchdog, перезапускает BibClientService при падении
│
└── Браузер (любое устройство в сети)
    ├── :8080/admin.html      ← веб-панель администратора
    └── :8080/operator.html   ← веб-панель оператора
```

## Компоненты

### BibClient

Запускается на каждом управляемом ПК. Отображает полноэкранный экран блокировки и выполняет команды от сервера.

**Ключевые модули:**
- `MainWindow.xaml.cs` — экран блокировки, ввод пароля для офлайн-разблокировки
- `PolicyEngine.cs` — обрабатывает входящие команды (30+)
- `SettingsManager.cs` — хранит настройки и SHA256-хеш пароля в `settings.json`
- `KeyboardHook.cs` — перехватывает системные комбинации (Alt+Tab, Alt+F4 и др.)
- `RegistryPolicyEngine.cs` — применяет групповые политики через реестр Windows
- `Watchdog.cs` — мониторинг состояния и связи с сервером

**Офлайн-режим:** если сеть недоступна, клиент может работать автономно. При `LockOnOffline=true` блокирует ПК при потере связи во время платной сессии. Разблокировка возможна по паролю администратора без сети.

---

### BibClientService

Windows-сервис (работает в фоне, не требует входа пользователя). Каждые 3 секунды проверяет, запущен ли процесс `BibClient.exe`, и перезапускает его при падении (cooldown 5 сек). При плановом обновлении ждёт до 30 минут через флаг-файл.

---

### BibClientGuardian

Watchdog-процесс, который следит за `BibClientService`. Перезапускает сервис при падении (cooldown 10 сек). Работает как скрытый процесс, использует named mutex для single-instance защиты.

---

### BibAdmin (десктоп)

WPF-приложение администратора. Подключается к серверу через SignalR (`/adminhub`) и управляет всеми клиентами.

**Страницы:**
- **ComputersPage** — список ПК, управление сессиями, передача сессий между ПК
- **OperatorsPage** — создание и управление учётными записями операторов
- **FinancePage** — история сессий, услуги, экспорт в CSV
- **SettingsPage** — глобальные настройки, смена пароля, ограничения

---

### BibAdminWeb

ASP.NET Core веб-сервер, выполняет две роли:
1. **Хаб SignalR** — ядро системы, через которое проходят все команды между Admin и Client
2. **Веб-интерфейс** — отдаёт статические HTML/JS/CSS страницы и REST API

**SignalR хабы:**
| Хаб | Путь | Кто подключается |
|---|---|---|
| `AdminHub` | `/hub` | BibClient (клиентские ПК) |
| `AdminWebHub` | `/adminhub` | BibAdmin (десктоп администратора) |
| `OperatorHub` | `/webhub` | Браузер оператора |

## Поток данных

### Запуск сессии

```
Администратор
  → BibAdmin (нажимает "Старт")
    → SignalR /adminhub
      → AdminWebHub
        → AdminHub
          → SignalR /hub
            → BibClient (получает команду START_SESSION)
              → Показывает активную сессию, запускает таймер
```

### Офлайн-разблокировка

```
Сеть недоступна
BibClient → Пользователь вводит пароль
  → VerifyPassword(input, SHA256-хеш из settings.json)
    → true → разблокировка без обращения к серверу
```

## Хранилище данных

Все данные хранятся в JSON-файлах рядом с исполняемым файлом:

| Файл | Содержимое |
|---|---|
| `global_settings.json` | Глобальные настройки, операторы, тариф, пароль (хеш) |
| `settings.json` (клиент) | Настройки клиентского ПК, хеш пароля |
| `active_sessions.json` | Текущие активные сессии |
| `finance_sessions.json` | История завершённых сессий |
| `finance_services.json` | История услуг |
| `computers.json` | Реестр зарегистрированных ПК |

---

## Безопасность

- Пароль администратора хранится как SHA256-хеш, никогда не передаётся по сети в открытом виде
- Пароли операторов хешируются перед сохранением
- Веб-сессия администратора и оператора основана на случайном токене (GUID), хранится в HttpOnly cookie, живёт 24 часа
- Система работает только в локальной сети (без публичного доступа)

## Планируемые изменения архитектуры

- **Мобильный клиент** — приложение для Android/iOS, которое будет выдаваться в аренду как заблокированное устройство. Управляется тем же сервером через тот же SignalR-хаб.
- **Мобильное управление** — оператор управляет сессиями с телефона через адаптивный веб-интерфейс.
- **База данных** — замена JSON-файлов на SQLite или PostgreSQL при масштабировании свыше 50 ПК.
- **HTTPS** — шифрование трафика при выходе за пределы локальной сети.
