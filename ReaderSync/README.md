# ReaderSync — автообновление базы читателей из UZNEL

Робот заходит на сайт UZNEL, сохраняет список читателей в Excel и отдаёт его серверу
BibAdminWeb на этом же компьютере. Работает по расписанию: каждый день в 19:00; если вечером
не получилось — повтор в 08:00.

## Установка (один раз, на компьютере с сервером BibAdminWeb)

1. Скопировать папку `ReaderSync` на сервер.
2. Запустить `setup.cmd` **от имени администратора**. Он создаёт отдельное окружение Python
   в этой папке (`venv`), скачивает браузер в `browsers` и создаёт два задания Планировщика.
3. Открыть `config.ini`, вписать логин и пароль UZNEL, проверить адрес сервера и путь к файлу ключа.
4. Проверочный запуск с окном браузера, без отправки на сервер:
   `run_sync.cmd --headed --dry-run --from 01-10-2026`
5. Первая полная загрузка базы: `run_sync.cmd --full`

Сервер BibAdminWeb должен быть обновлён до версии с автообновлением и запущен — при запуске он
создаёт файл ключа `data\reader_sync_token.txt`.

## Как это работает

- Обычный запуск берёт читателей, зарегистрированных или изменённых с прошлого успешного
  запуска (с запасом в несколько дней). Первый запуск и `--full` загружают всю базу.
- Сайт отдаёт не больше 5000 строк за раз, поэтому большой период робот сам делит на части.
- Читатели в базе BibAdminWeb только добавляются и обновляются, удаления нет.
- Результат последнего запуска виден в админке на странице «Читатели»; там же кнопка
  «Обновить сейчас».

## Если что-то сломалось

- Журнал: `logs\sync_ГГГГММДД.log` — в нём шаг, на котором остановился робот.
- Снимок экрана и HTML страницы в момент ошибки: папка `debug`.
- Если сайт поменял вёрстку — все «адреса» кнопок лежат в `uznel_selectors.py`.
- Журналы, снимки и оставшиеся выгрузки удаляются сами через 14 дней (в них есть данные читателей).
